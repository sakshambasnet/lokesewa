## Placement rules

| You are creating...             | Put it in                                                              |
| ------------------------------- | ---------------------------------------------------------------------- |
| A new route/screen              | `app/…` (thin) + logic in `src/features/<feature>/`                    |
| A component used by one feature | `src/features/<feature>/components/`                                   |
| A component used by 2+ features | `src/components/ui/` (generic, no business logic)                      |
| A hook that calls data          | `src/features/<feature>/hooks/`                                        |
| A pure helper (no React)        | `src/lib/` or `<feature>/<name>.ts` if feature-specific                |
| SQLite read/write               | `src/data/local/repositories/`                                         |
| Supabase call                   | Feature `*.service.ts` using client from `src/data/remote/supabase.ts` |
| Zod schema                      | `src/schemas/`                                                         |
| DB schema change                | `supabase/migrations/` (new file, never edit an applied one)           |
| Server logic with secrets       | `supabase/functions/<name>/`                                           |

## Naming

- Components: `PascalCase.tsx` (`QuestionCard.tsx`)
- Hooks: `useCamelCase.ts` (`useMockTest.ts`)
- Stores: `<name>.store.ts`; services: `<name>.service.ts`; repositories: `<name>.repo.ts`
- Edge Functions & route folders: `kebab-case`
- SQL: `snake_case` tables (plural) and columns
- Migrations: `YYYYMMDDHHMMSS_short_description.sql`

## Import rules

- Use the alias: `import { Button } from '@/components/ui'`.
- From another feature, import **only** its `index.ts`: `import { useEntitlement } from '@/features/subscription'`.
- `app/` may import features; features must never import from `app/`.
- `src/data` must never import from `src/features`.
